Real-Time WebSocket Protocol (RFC 6455)

Sharada uses persistent full-duplex WebSocket connections for lightning-fast E2EE message routing, live presence, and WebRTC peer-to-peer signaling for voice/video calls.

Port 8080 /ws

Handshake & Connection Parameters

Connect with either query parameters or the Authorization header:

ws://localhost:8080/ws?token=<session_token>&v=1.4.3
Parameter Location Description
token Query parameter Active session token generated from /api/auth/login
v Query parameter Client version (e.g. 1.4.3). If <= 1.4.2, server pushes mandatory update notice
Authorization Handshake Header Bearer <session_token> format

Event Framing Specification

Every packet sent or received over the socket is serialized JSON conforming to this schema:

{ "type": "message", "channel_id": "chan-general", "target_id": "optional-user-id", "sender_id": "user-uuid-1", "sender_name": "camper", "payload": { ... }, "timestamp": "2026-11-16T17:20:00Z" }

Client-to-Server Events (Whitelisted)

To prevent remote injection attacks and unauthorized event spoofing, the server enforces an explicit whitelist of events permitted from clients. Injected events like session_revoked or raw message from client sockets are immediately dropped.

Event Type Payload Structure Description
typing { "channel_id": "chan-..." } Notifies active channel members that the current user is typing. Verified against channel membership.
call_offer { "sdp": "...", "target_id": "...", "channel_id": "..." } Initiates WebRTC call negotiation. Dispatches SDP offer to recipient or voice room members.
call_answer { "sdp": "...", "target_id": "..." } WebRTC SDP answer from call recipient.
call_candidate { "candidate": "...", "target_id": "..." } ICE candidate trickle for NAT traversal and direct P2P audio/video streaming.
call_join / call_leave { "channel_id": "voice-..." } Participant join/leave events for persistent group voice rooms.
call_reject / call_busy { "target_id": "..." } Call rejection or line busy status signal.

Server-to-Client Events (Broadcast & Targeted)

Events dispatched from the hub to connected clients:

Event Type Targeting Policy Description
message Channel Members Only New encrypted (E2EE) or server-stored message arrived. Payload contains full Message object.
user_online / user_offline Global Broadcast Presence state change of a user.
message_reaction Channel Members Only Emoji reaction was added or toggled on a specific message.
messages_read Channel Members Only Messages up to a specific timestamp were marked as read.
session_revoked Target User Devices Device session was terminated remotely. Triggers immediate local token purge and logout.
system_alert Target User Critical security or maintenance alert delivered straight into the system channel.

Sharada Security & Version Quarantine System

Architectural deep dive into password cryptography, strict version gating, two-factor authentication, and anti-tampering defenses implemented in Sharada Core v1.4.3.

Verified Hardened

Argon2id + Bcrypt (v2) Password Hashing

To protect passwords against massive GPU/ASIC hardware cracker clusters and database dump compromises, Sharada employs a two-tier hybrid hashing scheme:

// Format: v2$<argon2id_base64>$<bcrypt_hash> // 1. Password + Salt processed via Argon2id: // - Memory: 64 MB // - Iterations: 2 // - Parallelism: 4 threads // 2. Resulting key hashed via Bcrypt (Cost 12)

Even if a raw database dump is leaked, attackers cannot bypass the 64 MB RAM requirement of Argon2id. Legacy hashes (base64$base64) are transparently migrated to v2$ on successful login.

Onboarding Lifecycle & 2FA Windows

Zero user registration without explicit administrative invite:

State Window Action on Timeout
INVITED 48 Hours Account and credentials permanently purged from database.
PENDING_2FA 24 Hours Must bind TOTP authenticator app. Purged if unverified within 24h.
ACTIVE Indefinite Full access granted. Regular logins require 6-digit TOTP code.
ARCHIVED 7 Days Self-deleted or admin-archived. Can be restored before automatic purge.

Client Version Gating & Legacy Cutoff (v1.4.3)

Due to critical security patches addressing channel IDOR and WebSocket broadcast leaks, clients with version <= 1.4.2 are quarantined by the server:

HTTP/1.1 426 Upgrade Required Content-Type: application/json { "error": true, "message": "Пожалуйста, обновите свой клиент sharada! В обновлении 1.4.3 исправлены критические проблемы безопасности. Версии 1.4.2 и ниже заблокированы." }
  • Channel Quarantine: GET /api/channels filters out all private and group chats, returning solely the system channel system-sharada-<userID> with the security notice.
  • Action Lockdown: All message dispatching, reactions, channel creation, and profile modifications return HTTP 426 Upgrade Required.
  • Auto-Updater Integration: Built-in 1.4.2 clients automatically trigger their update modal with the direct download button for version 1.4.3.
